# Parcelpoint architecture

Parcelpoint is a small, made-up parcel tracking company. Merchants create shipments through its API, carriers report where each parcel is, and a worker turns their events into the tracking page a customer sees. Every diagram on this page and beside it is made from a file in this repository by `plotwork generate`; none is drawn by hand.

## TL;DR

| Question | Answer |
|---|---|
| What runs in production? | The tracking API and the carrier event worker on Azure App Service, with Postgres, blob storage for label PDFs, and a Service Bus queue for carrier events. See [infra.diagram](./infra.diagram), made from `infra/terraform`. |
| What runs on a laptop? | The Docker Compose stack below, made from `compose.yaml`. |
| What does the API offer? | Ten endpoints in three tags, made from `api/openapi.json`: [by tag](./api.diagram) and [who may call each](./api-access.diagram). |
| Where is the data? | Five tables, made from `db/schema.sql`. See [database.diagram](./database.diagram). |

## The stack on a laptop

`docker compose up` starts the web app, the API, the worker, Postgres, and RabbitMQ. The diagram is written into this fence by `plotwork generate`; change it in `docs/architecture.services.overrides.json`, never in the fence.
